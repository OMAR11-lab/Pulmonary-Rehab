# Respira — Bronchial Asthma Pulmonary Rehabilitation Platform

A responsive, role-based web application for clinician-led bronchial asthma pulmonary rehabilitation. The first implementation is based on the supplied thesis and departmental proposal. **This initial release supports bronchial asthma only.** Other respiratory diagnoses are intentionally excluded from the patient data model and user interface.

## Technology

- React + TypeScript + Vite
- Supabase Auth, PostgreSQL, Row Level Security and Edge Functions
- Vercel-compatible static frontend deployment
- Tailwind CSS utilities plus a project stylesheet

## Roles

- **Administrator:** account management, platform configuration, exercise content governance and operational oversight.
- **Pulmonologist:** assigned asthma patients, clinical assessments, individualized rehabilitation plans, adherence review and follow-up.
- **Patient:** access to their own record and assigned rehabilitation plan, approved demonstrations, self-reported completion and progress.

## Implemented application modules

- **Foundation and access control:** responsive React/TypeScript application, Supabase email/password staff authentication, role-aware routes, administrator account invitations, audit logs and row-level security.
- **Patient management:** bronchial-asthma-only registration, adult age restriction (18+), clinician-scoped patient directory, search, record summary and edit workflow.
- **Patient activation:** single-use 24-hour invitation link generated by a protected Edge Function; the patient verifies the phone number already stored in the patient record by SMS OTP. A database transaction securely links the Auth user to the patient record. Patient login uses phone OTP.
- **Clinical assessments:** repeatable baseline, interim, post-program and follow-up records for history, smoking history, comorbidities, medications, examination, clinician-recorded eligibility review, mMRC, ACT, 6MWT, spirometry, anthropometry/BMI, HADS and education delivered.
- **Exercise and education library:** thesis-derived aerobic, resistance, breathing, flexibility and education entries; content editing, version increments and draft/approval controls; optional HTTPS demonstration links; patient accounts only see active approved entries. Specialist MI-E/HFCWO items are explicitly marked as clinician-managed.
- **Rehabilitation plans:** clinician-created draft plans with editable program duration, weekly frequency, session-duration range and activity-level frequency/sets/repetitions/duration/intensity/rest/notes. Plans become patient-visible only after clinician activation/approval.
- **Patient portal and adherence:** patients can view approved plans and submit self-reported session completion, minutes, difficulty, symptoms and reasons for missed activity. Clinicians can review these logs.
- **Follow-up and notifications:** clinician follow-up tasks, in-app notifications when a patient submits an activity update and patient notification when a plan is approved. This release does not send SMS/push reminders or run an autonomous reminder scheduler.
- **Reports:** descriptive baseline-to-post/follow-up outcome comparison, self-reported activity totals, CSV export and print-to-PDF through the browser. Missing measurements remain missing; the app does not interpret clinical significance.

## Clinical scope and source handling

The supplied thesis describes adults aged 18 years or older with controlled bronchial asthma, no exacerbation during the preceding four weeks, persistent symptoms such as dyspnea or reduced exercise tolerance, and willingness to participate. It lists significant alternative respiratory disease, unstable cardiovascular or musculoskeletal conditions, severe cognitive impairment, recent structured rehabilitation and pregnancy among exclusions. These are captured in the clinical implementation plan; the software must not automatically determine eligibility.

The thesis describes baseline assessment using history and examination, mMRC, ACT, 6MWT, spirometry and HADS, with BMI also recorded in the departmental proposal. Rehabilitation content includes aerobic training, resistance training, respiratory muscle/breathing exercises, asthma and medication education, inhaler technique, symptom recognition/self-management and psychological support.

**Clinical configuration requiring review:** the thesis contains differing aerobic intensity descriptions (70–85% estimated maximum heart rate and 40–60% estimated maximum heart rate, with Borg dyspnea 3–5 also mentioned). No default intensity or automatic target calculation is enabled in this release. The thesis also describes pre-session peak expiratory flow measurement and deferring exercise below 60% of personal best or when symptoms are present; this must be configured only after departmental approval. Clinical staff remain responsible for eligibility, prescription, progression, safety and escalation decisions.

## Local setup

1. Create a Supabase project.
2. Copy `.env.example` to `.env.local` and set:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY` (or the project's publishable key)
3. Install dependencies and run the frontend:

   ```bash
   npm install
   npm run dev
   ```

4. Apply the migration:

   ```bash
   supabase login
   supabase link --project-ref YOUR_PROJECT_REF
   supabase db push
   ```

5. In Supabase Authentication → URL Configuration, set the Site URL to the Vercel deployment and add `https://YOUR_VERCEL_DOMAIN/set-password` to the allowed redirect URLs. Configure an SMTP provider so administrator invitation emails can be delivered.

6. Configure Supabase Authentication → Providers → Phone and an SMS provider (for example, an institution-approved Twilio or supported provider). Test SMS delivery and ensure phone numbers are stored in E.164 format. Email SMTP is also required for staff invitations.

7. Create the first administrator in Supabase Authentication (Dashboard → Users → Add user), then run this once in the Supabase SQL Editor:

   ```sql
   update public.profiles
   set role = 'admin', is_active = true
   where email = 'YOUR_ADMIN_EMAIL';
   ```

8. Deploy the protected account-invitation and patient-invitation functions:

   ```bash
   supabase functions deploy admin-create-user
   supabase functions deploy create-patient-invitation
   supabase secrets set APP_URL=https://YOUR_VERCEL_DOMAIN
   ```

   Supabase provides `SUPABASE_URL`, `SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` to deployed Edge Functions. Set the `APP_URL` Edge Function secret to your deployed frontend URL so invitation links open the password-setup screen. Do not add the service-role key to Vercel frontend environment variables or commit it to Git.

9. Add the frontend environment variables to Vercel and deploy from the selected GitHub branch.

## Safety and privacy notes

- A patient can only access their own linked record and assigned program.
- A pulmonologist can access only records assigned to that clinician.
- An administrator can manage accounts and platform-level records.
- Patient invitation token hashes are not exposed through authenticated table queries. A server-side function issues the invitation; a security-definer SQL transaction checks the verified phone, token expiry and single-use state before linking the account.
- Patient-reported activity is self-reported adherence, not objectively verified exercise performance.
- The application does not replace prescribed asthma medication, an asthma action plan, urgent assessment or direct clinical advice.
- Before live use, the department must approve eligibility, clinical forms, safety thresholds, patient-facing content, escalation contacts, consent and data governance.
